# Диагностика и обработка ошибок

## Политика

- `DEBUG`, `INFO`, `WARNING`, `ERROR` — только журнал.
- `CRITICAL` — журнал + сохранённая активная проблема на главном экране.
- Критическая ошибка не требует исправности `stepper.db`. Она сохраняется в `SharedPreferences` отдельным маленьким хранилищем.
- Очистка списка критических ошибок не удаляет журнал.

## Ограничение журнала

Используется 8 файлов по 6 МиБ:

```text
stepper.log
stepper.log.1
...
stepper.log.7
```

Максимум около 48 МиБ. Ротация выполняется до добавления новой записи и после записи.

## Что считается критическим

К критическим относятся события, при которых приложение может продолжить работу с нарушением основного назначения или требует внимания пользователя:

- ошибка запуска foreground-службы;
- ошибка регистрации датчика;
- ошибка обработки показания датчика;
- невозможность создать текущую запись БД;
- ошибка применения/отката резервной копии;
- необработанное исключение потока приложения.

Отсутствие поддерживаемого аппаратного датчика само по себе не считается повреждением приложения: это обычное состояние совместимости и записывается как `ERROR`.

## Экспорт

Пользователь может экспортировать журнал из настроек. Файл создаётся как ZIP и не изменяет исходный журнал.
