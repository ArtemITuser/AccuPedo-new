# Шагомер — матрица надёжности v0.7.0

## Основной счётчик

1. `TYPE_STEP_COUNTER` является единственным основным онлайн-источником.
2. Каждое показание получает `bootId`, значение датчика, timestamp сенсора, `elapsedRealtime`, UTC-время и локальную дату.
3. Предыдущее значение хранится в SQLite, а не только в памяти процесса.
4. `sensor_sample`, `step_event`/`unresolved_step_event`, агрегаты и новое `last_sensor_value` проходят одной SQLite-транзакцией.
5. Уменьшение счётчика не трактуется как отрицательное число шагов.

## Перезагрузка

`BOOT_COUNT` используется как основной идентификатор загрузки. После reboot новый `bootId` автоматически образует новую последовательность датчика.

## Сдвиг часов

`TimeIntegrity` сравнивает wall-clock и monotonic elapsed time. При существенном расхождении дельта шагов не приписывается подозрительной дате автоматически, а сохраняется в `unresolved_step_events`.

## UI и батарея

Главный экран создаёт сегодняшнюю нулевую запись при первом запуске, поэтому пользователь не попадает в пустой интерфейс до первого сенсорного события.

Activity опрашивает базу только в состоянии `RESUMED`. Фоновый сервис не зависит от Activity.

Виджет и постоянное уведомление обновляются не чаще одного раза в минуту.

## Android

Фоновый подсчёт реализован отдельным foreground service типа `health`. Сервис использует `ACTIVITY_RECOGNITION`, не требует GPS и не держит отдельный wake lock.

`BOOT_COMPLETED`, `MY_PACKAGE_REPLACED`, `TIME_SET` и `TIMEZONE_CHANGED` могут восстановить службу при включённом пользователем режиме отслеживания.

## Health Connect

Health Connect является внешним источником. Перед созданием клиента проверяется доступность провайдера, поэтому отсутствие Health Connect не ломает запуск приложения.

Для чтения шагов используется Aggregate API, а не простое суммирование сырых `StepsRecord`.
