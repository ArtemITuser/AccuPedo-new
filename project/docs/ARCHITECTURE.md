## Источники

1. `sensor` — приоритетный источник собственного измерения.
2. `health` — внешний агрегированный источник.
3. `accupedo.csv` / `accupedo.db` — импорт истории.

Один день не должен складываться из нескольких зеркальных источников. Это принципиальная защита от двойного учёта.

## Время

`wallClock` нужен для календаря, `elapsedRealtime` — для длительности внутри загрузки, `BOOT_COUNT` — для разграничения перезагрузок. Смена часового пояса не является сменой даты сама по себе: дата определяется по локальной зоне момента наблюдения.

## Сбой датчика

Если значение `TYPE_STEP_COUNTER` уменьшается внутри одной `bootId`, дельта не добавляется. Записывается `SENSOR_COUNTER_RESET`, чтобы история не получила отрицательную или огромную ошибочную дельту.

## Фоновая работа

Foreground service нужен только в режиме непрерывного отслеживания. UI не удерживает service и не запускает отдельные фоновые таймеры. Пока приложение открыто, UI обновляется лёгким 2,5-секундным опросом локальной БД; после закрытия экрана это прекращается.


## Атомарность

В v0.6 `SensorEvent` обрабатывается целиком в `StepperDb.processSensorReading()`. Обновление `boot_sessions.last_sensor_value` происходит в той же транзакции, что и запись delta. Это является обязательным инвариантом точности.

## UI-состояние и расход энергии

`StepperLiveState` не заменяет базу данных. Это только внутрипроцессный снимок для экрана «Сегодня». Сервис публикует его **после** успешного коммита SQLite-транзакции. Если процесс завершён, приложение при следующем запуске читает канонические данные из `stepper.db`.

Activity не выполняет постоянный опрос базы. В состоянии `RESUMED` один раз в минуту обновляются вторичные представления (например, почасовой график и история). Основные значения приходят через `StateFlow` при фактическом изменении счётчика. Это уменьшает пробуждения, чтение SQLite и лишние перерисовки UI.

## Стратегия батареи

Основной источник — аппаратный `TYPE_STEP_COUNTER`. Для слушателя применяется пакетирование до 60 секунд; накопительный счётчик не теряет шаги из-за задержки доставки. Запасной `TYPE_STEP_DETECTOR` использует окно 15 секунд, чтобы сохранить приемлемую отзывчивость. Постоянный `WakeLock` и GPS в обычном режиме отсутствуют. Виджет и foreground-уведомление обновляются не чаще раза в минуту.

Приложение **не запрашивает автоматически** исключение из оптимизации батареи. Пользователю показывается состояние энергосбережения/фоновых ограничений и предоставляется переход в системные настройки. Это позволяет сохранить нормальную автономность и не маскировать возможные ограничения прошивки.

Android рекомендует выбирать специализированные API для фоновых задач и не выполнять работу чаще необходимого; foreground service оправдан здесь тем, что непрерывный подсчёт шагов является заметной пользователю долгосрочной фитнес-функцией.
