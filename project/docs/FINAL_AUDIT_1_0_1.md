# Финальный аудит — Шагомер 1.0.1 build 10

## UI

Сделана Android-native модель интерфейса на Compose + Material 3. Функциональная модель близка к Accupedo: сегодня, история, графики, цели, источники данных, резервные копии, импорт Accupedo, Health Connect и состояние фонового режима.

Улучшения относительно исходной модели:

- главный экран не бывает пустым: сегодняшний день создаётся с нулевыми значениями;
- крупное кольцо цели + шаги + процент + километры + калории + активность;
- почасовая диаграмма встроена непосредственно в сегодняшний экран;
- история открывается по дням;
- графики имеют День / Неделя / Месяц / Год и переключение метрики;
- появился отдельный экран Маршруты для GPS-записей;
- настройки показывают состояние датчика, фона, батарейной оптимизации и нераспределённых шагов.

## Единая логика данных

Основная БД `stepper.db` является канонической для шагов и статистики.

Источники:

1. аппаратный `TYPE_STEP_COUNTER`;
2. Accupedo CSV;
3. Accupedo SQLite;
4. Health Connect;
5. восстановленные после аномалии времени шаги.

Источники не складываются друг с другом. При наличии собственных сенсорных данных они имеют приоритет над внешним агрегатом. Импорт идемпотентен по ключу источника.

GPS вынесен в отдельную БД `stepper_location.db` намеренно: личная история маршрутов не нужна для обычного шагомера и может быть удалена без удаления шагов.

## Постоянное обновление БД

Сенсорный сервис получает накопительное значение `TYPE_STEP_COUNTER`, вычисляет дельту относительно состояния конкретной загрузки устройства и выполняет одну SQLite-транзакцию:

`sample -> delta -> event -> hourly -> canonical day -> last_sensor_value -> COMMIT`.

Состояние счётчика не хранится только в памяти процесса. После перезапуска службы оно считывается из `boot_sessions`.

База работает в WAL; для максимальной сохранности последних транзакций включён `synchronous=FULL`.

## Фон

Подсчёт выполняется независимым foreground service типа `health` на отдельном потоке сенсора. Activity не является частью механизма подсчёта.

Поддержаны:

- `START_STICKY`;
- `BOOT_COMPLETED`;
- `MY_PACKAGE_REPLACED`;
- отдельная обработка изменения времени/часового пояса;
- обновление уведомления и виджета не чаще одного раза в минуту.

ОС или прошивка всё равно имеют право ограничить процесс. Проект минимизирует вероятность остановки, но не выдаёт невозможную гарантию.

## Резервные копии

Файл `.stepperbackup` содержит versioned manifest, консистентный snapshot основной БД, settings и при наличии GPS-базу. Snapshot формируется через `VACUUM INTO`, поэтому backup не является просто копированием живого WAL-файла.

При восстановлении:

- проверяется структура архива;
- проверяется `integrity_check` обеих БД;
- проверяются SHA-256 и размеры;
- рабочие файлы сначала страхуются rollback-копиями;
- только после успешной проверки выполняется замена.

SAF используется для `CreateDocument` / `OpenDocument`, поэтому один и тот же механизм работает с локальным хранилищем и провайдерами, например Google Drive.

## Длина шага

Базовая формула:

`distance = steps × stepLength`.

Базовая длина шага задаётся пользователем.

Опциональная автокоррекция ведёт отдельные профили:

- ходьба;
- быстрая ходьба;
- бег;
- утро / день / вечер.

Обучение разрешено только после качественной GPS-сессии и ограничено минимальными условиями. Новое наблюдение влияет на профиль плавно (EMA 80/20) и ограничено ±15% за одну сессию.

## GPS / Google Maps

GPS не нужен для обычного подсчёта и по умолчанию выключен.

Пользователь запускает явную `GPS-прогулку`. Для неё включается FGS `health|location`, собираются точки с отбрасыванием очевидных скачков, а маршрут пишется в отдельную БД.

Для просмотра доступны:

- список маршрутов;
- время, дистанция, число шагов, число точек и средняя точность;
- GPX-экспорт;
- открытие начала/конца маршрута в Google Maps.

Полный встроенный Google Maps SDK сознательно не обязателен: он требует API-ключ и подключение Google Maps Platform, а сохранение GPS-трека и его экспорт полезны и без этого.

## Виджеты

Один адаптивный Glance-виджет предоставляет несколько композиций в зависимости от размера:

- малый 2×1 — шаги + километры;
- стандартный — шаги + километры + процент цели;
- крупный — дополнительно цель, активность и калории.

Это лучше одного жёсткого layout и соответствует рекомендациям Android по responsive widgets.
