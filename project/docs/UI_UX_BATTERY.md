# UI/UX и автономность — 1.0.6 build 15

## Основной принцип

Интерфейс не является частью механизма подсчёта. Activity может быть закрыта, пересоздана или вообще отсутствовать; `StepTrackingService` продолжает принимать датчик и записывать канонические данные.

## Обновление интерфейса

`StepperLiveState` — только внутрипроцессный снимок для оперативного экрана «Сегодня». Он публикуется после успешного коммита SQLite.

Экран «Сегодня» подписан на `StateFlow`, поэтому исчез постоянный опрос БД раз в 4 секунды. Почасовой график и вторичные списки перечитываются один раз в минуту, только пока Activity находится в `RESUMED`.

Это уменьшает:

- обращения к SQLite;
- пробуждения процессора;
- лишние запросы к истории;
- количество ненужных перерисовок Compose.

## Подсчёт и аккумулятор

Основной источник — `TYPE_STEP_COUNTER`.

Параметры регистрации:

- `SENSOR_DELAY_NORMAL`;
- пакетирование до 60 секунд;
- без постоянного `WakeLock`;
- без GPS в обычном режиме;
- без секундного таймера;
- обработка на отдельном `HandlerThread`.

`TYPE_STEP_COUNTER` — накопительный источник в пределах загрузки устройства. Задержка доставки допустима, а число шагов рассчитывается по разнице накопительного счётчика, поэтому ожидание пакета не создаёт пропуска в истории.

Запасной `TYPE_STEP_DETECTOR` использует пакетирование до 15 секунд, чтобы резервный режим оставался отзывчивым.

## Обновление виджета и уведомления

Виджет и постоянное уведомление обновляются не чаще одного раза в минуту. Показание каждого отдельного шага не вызывает UI-операцию.

## Оптимизация батареи

Приложение не добавляет себя в исключения из системной оптимизации автоматически. Вместо этого:

1. показывает текущее состояние обычной оптимизации;
2. показывает системный режим энергосбережения;
3. показывает явное фоновое ограничение приложения, если Android его сообщает;
4. даёт пользователю открыть системный экран управления батареей.

На прошивках Xiaomi/HyperOS дополнительно проверяются собственные ограничения автозапуска/фоновой работы.

## Критические ошибки

Ошибки UI не останавливают подсчёт. Ошибка публикации `StepperLiveState` записывается в диагностический журнал, а сенсорная транзакция остаётся независимой.

Критические ошибки подсчёта, БД или foreground service выводятся на главном экране и одновременно попадают в ограниченный журнал диагностики.
